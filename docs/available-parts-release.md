# Available-parts generation: release verification

Verified on 2026-10-25 against the private production site, https://lego-nova.vercel.app.

New generated models and edited copies cannot enter the collection without a server-owned publication receipt. The server derives quantities from immutable model bytes, validates physical part definitions against its installed library, renders the captured model, refreshes every required LEGO element, and checks exact identity, colour, price, stock and combined quantity limits. Every observation must be at most 600 seconds old at publication. The bytes exposed by downloads must match the receipt and quote SHA-256.

There is no generation setting that disables these checks. A failure retains working files and returns repair feedback; it does not create a completed card. Previously saved models have explicit legacy records and retain their original bytes. Current availability expires independently of continued access to an approved model.

## Access and download verification

- The worker and Vercel API reject unauthenticated requests with HTTP 401. An authenticated cross-origin request receives HTTP 403.
- The unfinished car's chat artifact download received HTTP 409. Direct `/files/output/...` access received HTTP 404.
- The Vercel MPD download matched the approved model hash. The approved GLB download was valid and contained 405,804 bytes. The generated collection ZIP contained only approved model files and their permitted sidecars.
- Both generated models present before this release retained their exact hashes. All five gallery examples remained accessible.
- Chrome displayed `All parts available`, 22/22 coverage, exact element IDs, individual order limits, USD prices, and conditional fees. The automatic car assembly PDF remained available (seven pages).
- There were zero cart intents for the three test revisions. The total cart-intent count stayed at four throughout these tests. No LEGO cart additions or checkout operations occurred.

## Automated checks

- 13 strict physical-inventory tests.
- 19 purchasing, catalogue policy and PostgreSQL integration tests.
- 79 backend tests across the integration selection and focused regression runs.
- Three Vercel proxy tests and a successful production frontend build.

Cases include nested/repeated quantities, exact mappings and colours, aliases and quantity aggregation, unsupported composites, altered embedded definitions, custom/scaled/mirrored geometry, missing prices or limits, stock changes after rendering, incomplete refreshes, outages, expiry during commit, immutable snapshot races, direct-write attempts, archive/artifact bypasses, cancellation, exhausted rendering/agent budgets, legacy cutover, and source-restricted TypeSafe fallback.

The new private tables have RLS plus explicit grants. Actual `anon` and `authenticated` reads/writes were denied. `lego_app` can insert and read publication records but cannot update or delete them. Final Supabase advisors reported zero security issues and zero warnings; the publication quote foreign key has a covering index. Existing informational findings concern the singleton catalogue pointer and currently unused indexes.
